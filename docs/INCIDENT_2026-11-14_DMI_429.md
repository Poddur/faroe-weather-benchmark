# Automatic collection incident — 14 November 2026 (HTTP 429)

- First automatic attempt: [GitHub Actions run 43649196446](https://github.com/Poddur/faroe-weather-benchmark/actions/runs/43649196446).
- Local verification: **14 tests passed**.
- Forecast step failed when DMI HARMONIE EDR returned **HTTP 429** on the Tórshavn request at `/harmonie_dini_sf/instances/2026-11-14T000000Z/position`.
- The run completed with failure, created a persistent tracking issue [#1](https://github.com/Poddur/faroe-weather-benchmark/issues/1), and uploaded diagnostic artifact **14135013042**. DMI observations were not fetched in that attempt because the forecast stage failed.
- This is a **remote rate-limit problem** and does not indicate a model physics, unit, or forecast-skill failure.

## Mitigation in source
- `src/collect_matched_forecasts.py`: sequential DMI requests with a 2.5-second minimum gap; bounded maximum five attempts honoring Retry-After and conservative exponential fallback.
- `src/fetch_dmi_observations.py`: the same controls for observation API calls.
- Regression tests simulate HTTP 429 followed by success.
- Operational workflow now triggers on collector-source changes, so the mitigation will receive a live test without requiring the user to manually start another workflow.

## Remaining limitation
Source-side rate limits are outside this system's control. A prolonged 429 series can still fail; such failures must remain visible, not be silently converted to success. Successful archives and new issues are independent.
